# Widget 接入指南

面向**要把轻语客服气泡嵌进自己网站的前端 / 运维开发者**。管理后台里点哪儿配白名单、复制嵌入代码，见[使用手册 §10](./使用手册.md#10-嵌入-widget)；Widget 底层调用的接口与错误码，见[开放 API 参考](./开放API参考.md)。

> 本文描述以 `widget/src/`（含协议层 `widget/src/core/`）源码为准。线上跑的是后端 jar 里的 `static/widget.js` 构建产物。

---

## 1. 嵌入代码

```html
<script src="https://<你的域名>/api/widget.js?appKey=<App Key>" defer></script>
```

放在 `</body>` 前，或 `<head>` 里加 `defer` / `async` 都可以——脚本会等 DOM 就绪再初始化，定位自身 `<script>` 时先用 `document.currentScript`，拿不到（`async`/`defer` 场景）再按 `src` 含 `widget.js` 查找。

| 项 | 说明 |
|---|---|
| `appKey`（查询参数） | 必填。缺了控制台警告 `[Qingyu Widget] 缺少 appKey，无法初始化`，不渲染 |
| `v`（查询参数，可选） | 接入配置页生成的代码带 `&v=1`，纯粹用于绕过缓存，Widget 不读它。`widget.js` 响应带 `Cache-Control: max-age=300`，升级后最多 5 分钟生效；想立刻生效就改 `v` 的值 |
| `apiBase`（查询参数，可选） | 开放 API 基地址，只在 `widget.js` 与后端不同源（如放在 CDN）时需要，须 URL 编码。不填时取脚本地址去掉末尾的 `/widget.js`，见 §7.2 |

Widget 不向宿主页面暴露任何全局变量或 JS API，也不读 `data-*` 属性——没有「打开面板」「设置用户信息」之类的编程接口。

⚠️ **页面里只放 App Key，永远不要放 App Secret**。浏览器侧靠 Origin 白名单鉴权；Secret 进了页面源码就等于公开，拿到它的人能以服务端身份调用并检索 `INTERNAL` 文档。

## 2. 外观与文案

外观不在嵌入代码里配，而是 Widget 启动时从 `GET /api/open/v1/widget/config` 拉取，改应用设置即可：

| 字段 | 来源 | 在 Widget 里的表现 |
|---|---|---|
| `appName` | 租户配置了对外品牌名（`tenant.display.name`）时用它，否则用应用名 | 面板标题；为空时显示「在线客服」 |
| `welcomeMessage` | 应用的欢迎语 | **首次**展开面板时作为一条 AI 消息插入；本地已有会话的老访客不再显示 |
| `themeColor` | 应用的主题色 | 气泡、标题栏、访客消息、按钮配色；为空时 `#0d9488` |
| `avatar` | 应用的头像地址（应用编辑弹窗里填） | 标题栏应用名左侧的 28px 圆形头像；为空、不是 http(s) 地址、或图片加载失败时不显示。只显示在标题栏，不显示在每条消息前（坐席接入后，坐席的消息也在同一面板里）。宿主页是 HTTPS 时头像也要用 https 链接，否则会被浏览器按混合内容拦截 |

固定不可配的部分：气泡在右下角（距右、下各 20px，56px 圆形），面板 360×520，`z-index: 2147483000`。整个 UI 挂在一个 Shadow DOM 里，宿主页面的 CSS 影响不到它，它也不污染宿主页面。

⚠️ `widget/config` 拉取失败（白名单不匹配、额度用尽、限流、网络错误……）时 Widget **完全不渲染**，只在控制台留一行 `[Qingyu Widget] 拉取配置失败，停止渲染`。这是有意的 fail-silent，不干扰宿主页面，但也意味着「气泡没出来」要先看控制台。

## 3. Origin 白名单

Widget 的请求不带任何密钥，服务端只认两样：`X-App-Id`（App Key）和浏览器自动附加的 `Origin` 头。所以**必须先把嵌入页的来源加进该应用的「Widget 允许来源域名」**，否则所有请求 403。

匹配规则（`OpenApiAuthService.isOriginAllowed`）：

| 规则 | 例子 |
|---|---|
| 精确匹配 `scheme://host[:port]` | 白名单 `https://www.example.com` 只放行这一个来源 |
| 协议不同不匹配 | 页面是 `https`，白名单写 `http://…` → 403 |
| 端口不同不匹配 | `http://localhost:5173` 与 `http://localhost:3000` 要分别写 |
| 主机不同不匹配，**不支持通配** | `example.com`、`www.example.com`、`m.example.com` 要逐个写，写 `*.example.com` 无效 |
| 不能带路径或末尾斜杠 | `https://www.example.com/` 永远匹配不上 |
| 白名单留空 | 该应用不开放 Widget，一律 403 `该应用未开放 Widget 接入` |

界面上是每行一个，存储时转成逗号分隔。开发、预发、生产用不同域名的话，全部写进去，或者给每个环境建一个应用。

⚠️ 白名单只能挡住**浏览器**里的冒用：非浏览器客户端可以随意伪造 `Origin`。它的定位是「让别的网站没法直接嵌你的 Widget」，不是访问控制——这正是访客身份只能检索 `PUBLIC` 文档的原因。别把敏感内容标成 `PUBLIC`。

## 4. 会话与访客标识

Widget **没有访客账号或用户 id 的概念**（不发 `userId`），唯一的身份是服务端生成的 `sessionId`。

| 项 | 行为 |
|---|---|
| 存储位置 | 宿主页面的 `localStorage`，键 `qingyu_widget_session_<appKey>`，值 `{"sessionId": "...", "createdAt": <毫秒>}` |
| 何时写入 | 每发一条消息，收到流的 `start` 事件时写入（顺带刷新 `createdAt`） |
| 本地有效期 | 距最近一次发消息 24 小时，过期即丢弃、下次发消息开新会话 |
| 作用范围 | 跟 `localStorage` 一样**按 origin 隔离**：`www.a.com` 与 `m.a.com` 是两个独立会话；同一 origin 的多个标签页共用一个会话 |
| 隐私模式 / 禁用存储 | 读写异常被吞掉，降级为「每次刷新都是新会话」，对话照常 |
| 一次咨询一个会话 | 会话被坐席结束或超时关闭后，Widget 丢掉本地的 `sessionId`，访客的下一条消息自动开一个新会话。结束时访客若开着页面，会当场看到「本次会话已结束」的提示 |
| 服务端找不到会话或会话已结束（404） | 自动清掉本地记录、以新会话把**这条消息**重发一次，访客无感；⚠️ 重发时**丢弃这条消息的附件**（它们绑在旧会话上），只保文字 |
| 会话已结束时转人工 / 传附件 | 清掉本地会话并提示「发送一条消息即可开始新会话」（新会话建立后附件按钮才可用） |
| 刷新页面 | 本地有 `sessionId` 就先 `GET /sessions/{id}`：会话仍在进行中就恢复历史（含卡片与附件，历史 AI 消息不带赞踩按钮）并连上坐席实时通道；已结束或已超时则丢掉，不恢复旧记录 |

想让访客在不同设备 / 子域名之间延续会话，Widget 目前做不到；需要的话用服务端身份自己调开放 API，把 `sessionId` 与你的用户体系关联。

## 5. 功能表现

### 5.1 对话与反馈

- 回复逐字流式显示；正文按**纯文本**渲染（不解析 Markdown、不解析 HTML）。
- 发送后在回复开始前显示「输入中…」；流中途断开会在已显示的半截后追加「回复中断，请重试。」，不会自动重发（重发等于重复计费）。
- 服务端返回 429 时提示「请求过于频繁，请稍后再试。」，其它错误提示「抱歉，服务暂时不可用，请稍后再试。」。
- 每条成功落库的 AI 回复带 👍 / 👎，点击即提交反馈，失败静默。

### 5.2 结构化卡片

AI 回复里可能夹带卡片（流式 `card` 事件，或历史消息的 `uiParts`）。Widget 支持的节点类型：

| 类别 | `type` |
|---|---|
| 容器 / 布局 | `card`（可带 `title`）、`row`、`column`、`list`、`actions`、`divider` |
| 展示 | `text`（`value`，`emphasis` 加粗）、`kv`（`label` + `value`）、`badge`、`image`（`src`，仅 http/https） |
| 交互 | `button`（`label`、`style`: `primary`/`danger`、`action`、`value`） |
| 表单 | `form`、`input`、`datetime`（日期）、`checkbox`、`select`、`submit` |

- **按钮动作**：`action` 只认三种协议——`url://<地址>`（新标签打开，仅 http/https）、`msg://<文本>`（以访客身份发出这段文本）、`copy://<文本>`（复制到剪贴板，按钮短暂显示「已复制」）。其它值视为无动作，回退为发送 `value`（没有就发 `label`）。协议合法但内容被拦下（如 `url://javascript:…`）时**点击无反应**，这是有意的 fail-closed。
- ⚠️ `copy://` 依赖 `navigator.clipboard`，只在 HTTPS（或 localhost）页面可用，HTTP 页面会显示「复制失败」。
- **表单**：点 `submit` 先做必填校验，通过后把各字段拼成 `字段名: 值` 多行文本，作为一条访客消息发出——没有独立的表单提交接口。
- 所有文本经 `textContent` 渲染，未知 `type` 静默忽略，畸形结构不会打断其余内容。

### 5.3 真人坐席

| 场景 | 表现 |
|---|---|
| 访客点标题栏「转人工」 | 还没发过消息时提示「请先发送消息开始会话，再申请转人工。」；否则调用转人工接口并提示「已为你转接人工，请稍候。」 |
| 消息命中转人工关键词 | 服务端自动转人工，回复「正在为您转接人工客服，请稍候...」 |
| 等待 / 人工处理中访客继续发消息 | AI 不再回答，回复固定提示「[会话已转接人工客服，请等待回复]」；消息照常保存，坐席已接管时实时推给坐席 |
| 坐席接入 / 交还 AI | 消息区居中提示「客服已接入，正在为您服务」/「已切回智能助手为您服务」 |
| 坐席发消息 | 带「客服」标记的气泡，与 AI 回复区分；可含图片与文件 |
| 坐席正在输入 | 显示「输入中…」 |
| 访客正在输入 | 已有会话时节流上报（≥ 3 秒一次），坐席侧可见 |
| 已读回执 | 坐席读过的最新一条访客消息下显示「已读」；访客侧只在**面板展开且标签页在前台**时才向坐席上报已读 |

坐席消息走一条独立的 SSE 长连接（inbox），首次发消息拿到会话后建立，断线按 1s 起、逐次翻倍、最长 15s 的退避自动重连，收到 401/403 停止重连；页面 `pagehide` 时关闭。

### 5.4 附件

- 输入框左侧 📎 按钮，**会话建立前是禁用的**（服务端要求上传时会话已存在），发出第一条消息后才可用。
- 选中即上传，成功后显示为待发送的文件名标签（可 × 移除），随下一条消息一起发出。⚠️ **附件必须配文字**，只有附件没有文字发不出去。
- 类型与大小限制由服务端校验（图片 png/jpg/webp/gif ≤ 5MB，pdf/doc/docx/xls/xlsx/txt/zip ≤ 20MB，单会话最多 20 个），Widget 不做前置检查；被拒时提示「附件上传失败，请重试」。完整规则见[开放 API 参考 §5.4](./开放API参考.md#54-post-chatfiles-上传附件)。
- 图片内嵌预览（点击新标签看原图），其它文件显示文件名 + 大小，点击下载。下载与预览都用 `fetch` 带鉴权头取回再转成 `blob:` URL，所以宿主页面的 CSP 需要允许 `blob:` 图片（见 §7.4）。

## 6. 调用量与限流

Widget 的每一个请求都计入应用的开放 API 限流（默认每应用 60 次/分钟，**所有访客共享**；另外每个访客 IP 20 次/分钟）：启动拉配置、每次发消息、inbox 每次（重）连、typing、已读上报都算。访客量一上来，默认值很容易打满，表现为回复提示「请求过于频繁」、甚至新访客的气泡直接不出现（配置拉取被 429）。

在接入配置页把该应用的「每分钟请求上限」调到与流量匹配的值。细则见[开放 API 参考 §3](./开放API参考.md#3-限流与额度)。租户月度额度用尽时，Widget 同样整体不渲染（配置拉取 403）。

## 7. 常见问题排查

先打开浏览器开发者工具：控制台看 `[Qingyu Widget]` 开头的警告，Network 面板看 `/api/open/v1/` 请求的状态码与响应体（`{"error":{"code":…,"message":…}}`）。

| 症状 | 看什么 | 原因与处理 |
|---|---|---|
| 气泡完全不出现 | 控制台 `拉取配置失败，停止渲染`；`widget/config` 状态码 | 403 `来源域名未授权` / `该应用未开放 Widget 接入` → §3；403 `QUOTA_EXCEEDED` → 额度用尽；403 `应用已停用` / `租户已被冻结` / `租户套餐已到期`；429 → §6；401 `无效的凭据` → `appKey` 抄错 |
| 气泡不出现，控制台 `缺少 appKey` / `未找到加载脚本` | `<script>` 标签 | `src` 没带 `appKey`；或脚本被打包工具改名 / 内联，`src` 里不再含 `widget.js` |
| `widget.js` 本身 404 | 直接访问脚本地址 | 地址少了 `/api`，或反代没把 `/api/` 转给后端 |
| 气泡出来了，发消息只回「服务暂时不可用」 | `chat/stream` 状态码 | 加载后白名单被改掉 / 额度中途用尽（403）；后端或模型故障（500）；参数错误（400） |
| 回复不逐字出现、整段一次性刷出 | 反代配置 | nginx 开着 `proxy_buffering`，SSE 被攒着不下发。按[部署文档](./部署文档.md)的反代配置关掉 buffering 并调大 `proxy_read_timeout` |
| 坐席回复要刷新才看得到 | inbox 请求是否一直挂着 | 同上的反代缓冲 / 超时问题；或 inbox 被 403 后已停止重连 |
| 附件按钮一直是灰的 | — | 还没发过第一条消息，属正常 |
| `copy://` 按钮总提示复制失败 | 页面协议 | 宿主页面是 HTTP，剪贴板 API 不可用 |

### 7.1 白名单明明写了还是 403

逐项对照 §3：多半是 `http`/`https`、`www` 有无、端口、末尾斜杠其中之一不一致。以 Network 面板里请求头 `Origin` 的**实际值**为准，原样复制进白名单。

还有一种少见情况：浏览器对**同源的 GET 请求不发 `Origin`**，后端会退而从 `Referer` 解析来源；若页面设置了 `Referrer-Policy: no-referrer`，两者都没有就会 403。这只在嵌入页与后端同源时出现。

### 7.2 反向代理与子路径

Widget 按以下顺序确定开放 API 地址：

1. 嵌入代码里显式给了 `apiBase` 参数，就用它；
2. 否则取脚本地址去掉末尾的 `/widget.js`——后端本来就在 `{API 基地址}/widget.js` 提供脚本，所以反代挂在子路径下（如 `https://x.com/qingyu/api/widget.js` → `https://x.com/qingyu/api`）不用做任何额外配置；
3. 都不满足时（脚本被改了名）回落到「脚本所在 origin + `/api`」。

用 CDN 或另一个域名托管 `widget.js` 时，必须显式给 `apiBase`，否则 Widget 会把 CDN 当成 API 地址：

```html
<script src="https://cdn.example.com/widget.js?appKey=<App Key>&apiBase=https%3A%2F%2Fcs.example.com%2Fapi" defer></script>
```

⚠️ 自托管的 `widget.js` 需要随后端升级同步更新，否则跑的是旧版本。

`/api/widget.js` 与 `/api/open/v1/**` 的 CORS 对任意来源开放且不带凭据（不用 cookie），反代不需要、也不应该再额外加 CORS 头，否则可能出现重复的 `Access-Control-Allow-Origin` 导致浏览器拒绝。

### 7.3 HTTPS 与混合内容

宿主页面是 HTTPS 时，`widget.js` 也必须从 HTTPS 地址加载——HTTP 的脚本会被浏览器当作混合内容直接拦截，而且 Widget 的 API 地址跟随脚本协议，脚本是 HTTP 则所有请求也是 HTTP。后端上 TLS 之后，记得把白名单里的来源同步改成 `https://`。部署步骤见[部署文档 §5.3](./部署文档.md#53-启用-https)。

### 7.4 宿主页面有 CSP

页面配置了 Content-Security-Policy 时，需要放行：

| 指令 | 需要加入 |
|---|---|
| `script-src` | 轻语后端的 origin（加载 `widget.js`） |
| `connect-src` | 轻语后端的 origin（所有 fetch 与 SSE） |
| `style-src` | `'unsafe-inline'`——Widget 在 Shadow DOM 里用内联 `<style>` |
| `img-src` | `blob:`（附件预览），以及卡片 `image` 节点可能引用的图片域名 |
