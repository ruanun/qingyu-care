## 6. 公开仓库的历史处理

公开到 GitHub 的仓库**不是**本仓库历史的镜像，而是一份**单 commit 快照**：

- 私有仓库（`g.ruanun.com/ruanun/qingyu-care`）保留完整 731 个 commit，作为开发档案与备份。
- 公开仓库由 `git checkout --orphan` 从当前工作区重建，只有一个无父提交的「初始提交」。

这样处理的三个理由：

1. **历史里有过期密钥**：第 1 节第 3 条那个本地会话 token 虽然早已失效、文件也已删除，但它仍存在于私有仓库的旧提交里。单 commit 快照让它根本不出现在公开仓库中，比依赖白名单更彻底。
2. **不提需求讨论过程**：提交信息里有大量安全审查细节（“第三轮安全审查 4 高 / 8 中”）、内部排障过程与未完成的取舍记录，这些更适合留在私有档案。
3. **避免误导**：`0.0.1-SNAPSHOT` 的迭代史对外部使用者没有价值，反会让“这项目是否可用”变成一道需读 700 条提交才能判断的题。当前文件树本身已经是自洽的成品状态。

⚠️ **两个仓库的历史是两条独立的线**：公开仓库不能往回 merge 私有仓库的历史（会把全部 commit 带回来）。后续同步走「新快照」方式：

```bash
git checkout --orphan public-snapshot   # 每次同步都重新开一个孤儿分支
git add -A && git commit -m "同步：<要点>"
git push github public-snapshot:main
git branch -D public-snapshot
```

或者直接 `git push github <私有分支>:main --force`——公开仓库会变成“只有一个提交、内容等于该分支最新状态”的快照。注意 `--force` 在这里是**预期行为**，不是事故。

⚠️ 公开仓库只有 1 个 commit，所以 CI 里的 gitleaks 全历史扫描实际只扫一个快照，**不能替代**私有仓库上的定期扫描。私有的 `.github/workflows/ci.yml` 仍按全历史扫描配置。
