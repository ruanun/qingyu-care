# 安全基线

> 相关：全局机制见 [`../../CLAUDE.md`](../../CLAUDE.md)，子系统细节见 [`子系统要点.md`](./子系统要点.md)，
> 改完要真机走的清单见 [`手工验证清单.md`](./手工验证清单.md)。

2026-09-03 全项目安全审查（6 高 9 中 13 低）修完后立下的不变量，改动相关代码前先读对应条目：

1. **平台管理员口令不写死**：`AuthService.init` 从 `qingyu.care.platform.admin-initial-password`（`QINGYU_ADMIN_INITIAL_PASSWORD`）取，为空则随机生成、只打一次 WARN。dev/test profile 固定 `admin123`（多条 IT 靠它登录）。`AuthServiceInitTest` 守着「不回落 admin123」。
2. **自助注册只能建新租户**：带 `tenantCode` 一律 403。租户 code 不是秘密，凭它加入曾等于自封任意租户的管理员。
3. **同租户「改他人」必须是管理员**：`UserController.updateUser` 先判 self / admin，坐席只能改自己。`User.password` 是 `WRITE_ONLY`，实体当响应体也不会带哈希。
4. **应用管理走 `ApplicationView`，密钥只给管理员**：list/get 全体成员可用（顶部选应用靠它）但坐席拿到的 `appSecret`/`webhookSecret` 为 null；create/update/delete/重置密钥/测试 Webhook 一律 `requireTenantAdmin`。⚠️ 脱敏不能在受管实体上 setter 置空（OSIV 会刷回库），必须走视图对象。
5. **五条出站路径共用一套防线**：HTTP 工具、网页抓取、Webhook 走 `PinnedHttpClientFactory`（钉 IP + 禁重定向 + 超时），MCP 走 `PinnedAddressResolverGroup`，OpenAPI schema 复用抓取器。⚠️ Webhook 回调地址落库前过 `SsrfGuard.assertAllowedHttpUrl`；`qingyu.care.webhook.allow-private-targets` 只在 test profile 为 true（IT 的接收端起在 127.0.0.1），它只跳过网段校验、不跳过钉 IP。`SsrfGuard.isBlocked` 手工补了 100.64/10（阿里云元数据 100.100.100.200 在这段）、192.0.0/24、198.18/15、240/4、NAT64。
6. **CORS 两套 + 不用 cookie**：`/open/v1/**` 与 `/widget.js` 任意来源、`allowCredentials(false)`；其余只放行 `qingyu.care.cors.allowed-origins`（默认空 = 拒绝一切跨域，前端与后端同源）。`sa-token.is-read-cookie: false`——SPA 只用 `satoken` 请求头，cookie 一开就是 CSRF 面。`CorsPolicyIT` 守着。
7. **异常处理器不回显 `e.getMessage()`**：`RuntimeException` 回「服务器内部错误（错误编号 xxx）」，编号进日志；`IllegalArgumentException` 归 400 且同样不回显。要给用户看的原因改抛 `InvalidOperationException` / `BusinessException`。
8. **前端退出登录走 `lib/session.performLogout`**：先调后端注销再清本地（含 `qingyu-current-app`）。
9. **`X-App-Id` 必须属于当前租户才进上下文**：`TenantInterceptor` 用 `findTenantIdById` 反查，不属于就忽略并 WARN（平台管理员豁免）；`WebhookDispatcher` 再兜一道「应用租户 == 事件租户」。`TenantInterceptorTest` 守着。
10. **模型 endpoint 落库前过守卫**：`ModelRouterService.requireValidEndpoint` 只在管理面入口（建 / 改 / 测试连接，含平台共享模型）调用，不进对话热路径；`qingyu.care.model.allow-private-endpoints` 只在 dev profile 打开（本机 Ollama）。单测里 `ModelRouterService` 是 mock，控制器测试不会真的解析 DNS。
11. **Swagger / metrics / DEBUG 日志基线关闭，只有 dev profile 打开**：三者的路径都在 Sa-Token 豁免名单里，「关掉」是唯一可靠手段。`ManagementEndpointsExposureIT` 守着基线形态（test profile 不含 dev）。
12. **开放 API 与登录都校验租户状态与 `expireTime`**：冻结或到期的租户，widget / 开放 API / 登录一起停。⚠️ `ApplicationRepository.findByAppKey` 带 `@EntityGraph(tenant)`——鉴权在拦截器阶段执行、没有 OSIV 的 EntityManager，懒加载的 `tenant` 一碰非 id 字段就是 LazyInitializationException，而拦截器的兜底 catch 曾把它静默吞成 500（现在会记日志）。
13. **开放 API 两层限流**：应用级（`default-rate-limit-per-minute`，应用可覆盖）之下再按「应用 + 客户端 IP」分桶（`per-client-rate-limit-per-minute`，默认 20，0 关闭）。⚠️ 第二层**只作用于访客路径**：它防的是「appKey 公开 + Origin 可伪造」下的匿名滥用；服务端路径持密钥才进得来，而接入方后端往往只有一个出口 IP，曾被一起压到 20 次/分钟（2026-09-25 修正，`OpenApiAuthInterceptorClientLimitTest` 守着）。客户端 IP 一律取 `getRemoteAddr()`（`OpenApiAuthInterceptor.resolveClientIp`，登录 / 注册 / 出图 / 审计同一口径），见第 37 条。
14. **知识库上传先校验再传 S3**：`getSize()` 闸门（`qingyu.care.knowledge.max-upload-bytes`，30MB）→ 非空 → 扩展名白名单（`UPLOAD_EXTENSIONS`，与 `detectDocumentType` 一一对应）→ 文件名截到 255；`documentRepository.save` 失败必须 `deleteFile` 回收对象。
15. **摄取走 `TikaTextExtractor` 流式抽取，两道上限**：`max-extracted-chars`（200 万，超出截断 + WARN）与 `max-chunks-per-document`（2000）。⚠️ `TokenTextSplitter.withMaxNumChunks` 到顶后会把**剩余全部文本追加成最后一块**，所以切完必须再 `subList` 一次，否则封顶形同虚设。不再用 Spring AI 的 `TikaDocumentReader`（要整文件 `byte[]` 且输出无上限）；`ParseContext` 刻意不放 `Parser`，不递归解析嵌入文档。
16. **附件单会话上限 + 孤儿 2 小时**：`ChatAttachmentService.upload` 先 `countBySessionId` 判 `max-per-session`（20）；`orphan-retain-hours` 从 24 缩到 2，它是无凭据灌存储的唯一落点。租户级存储配额另见第 28 条。
17. **Webhook 签名覆盖「时间戳.请求体」**：`WebhookSignature.sign(secret, timestampMillis, body)`，时间戳同时随 `X-Qingyu-Timestamp` 发出；接收方复算 + 5 分钟窗口 + 按载荷 id 去重。改契约在未上线的现在零成本，上线后别再动。
18. **Prompt 定界**：知识库正文包在 `<knowledge>`（`ChatServiceImpl.buildContext`）、工具返回包在 `<tool_result>`（`ToolResultDelimiter.wrap`，HTTP 工具与 MCP 都走它，截断作用在正文、标签不占额度），系统提示末尾固定追加 `DATA_GUARD_PROMPT` 声明标签内是数据不是指令。放在代码里而不是只改默认模板：模板已播种进库。是缓解不是根治。
19. **分析 rollup 有日期锁**：`AnalyticsRollupDao.tryLockDay` 用 `pg_try_advisory_xact_lock(classId, day)` 双参数形式，与文档处理互斥的单参数形式键空间互不重叠；抢不到返回 false、`backfill` 不计入成功。其余 7 个 `@Scheduled` 各有自己的互斥（文档咨询锁 / CAS 认领 / 消费组）或重复无害，不需要锁。
20. **依赖扫描是手动步骤**：`scripts/dep-audit.sh`（`-Pdepcheck` + `pnpm audit`），刻意不绑进 `mvn verify`，见脚本头注释。⚠️ `pnpm audit` 必须显式 `--registry=https://registry.npmjs.org`——npmmirror 之类的镜像没有 audit 端点，会报 `ERR_PNPM_AUDIT_ENDPOINT_NOT_EXISTS`；后端那半需要免费的 `NVD_API_KEY`，不给会在更新漏洞库时直接失败。
21. **反代场景必须配 `server.forward-headers-strategy: framework`**：nginx 终结 TLS 后后端收到的是 http，而浏览器 `Origin` 是 https——不读 `X-Forwarded-Proto` 的话 Spring 把**同源**请求判成跨域，撞上管理端默认为空的 CORS 白名单直接 403，**整个后台登录不了**，而浏览器里只显示「网络错误，请稍后再试」。⚠️ 前提是 8080 只经受信任的反代对外，别直接暴露公网。`CorsPolicyIT` 那两条（同源放行 / 反代终结 TLS 后同源放行）守着。⚠️ 这个策略同时接管了客户端 IP 的解析，反代必须配合「覆盖」转发头，见第 37 条。
22. **Vite 代理必须摘掉 `Origin` 头**：`changeOrigin: true` 只改 Host。不摘 Origin 的话后端看到 `Origin=localhost:5175` 而 `Host=localhost:8080`，判成跨域 → 403；而 5173 被占用时 Vite 会自动漂到 5174/5175，白名单永远追不上。走反代时前端与后端本就该视为同源。
23. **`allow-private-*` 开关的落库校验与出站校验必须看同一个开关**：`ApplicationController.requireValidWebhookUrl` 与 `RestClientWebhookHttpClient` 各有一道，只改一处会让开关半失效（出站放行、落库仍拒），本地联调根本配不上地址。⚠️ 集成测试发现不了——它们直接 `setWebhookUrl` 写库，绕过控制器。
24. **工具调用失败的日志要能区分「被守卫拦下」与「网络问题」**：`HttpToolCallback.describeForLog` 对守卫抛的 `IllegalArgumentException` 记完整消息（里面只有 host），其余异常只记类名（消息可能带含密钥的 URL）。MCP 侧复用同一方法，两条链路口径必须一致。
25. **⚠️ 本机若用 fake-IP 模式的代理，所有出站工具调用都会被 SsrfGuard 拒**：Clash 一类代理把域名解析到 `198.18.0.x`，而该段在黑名单里（RFC 2544 基准测试段，生产无正当用途）。症状是工具静默失效，日志现在会明写「已拒绝: <host>」。AI 对话不受影响（走 SDK 直连、不经守卫）。这是环境限制不是缺陷，别为此放宽黑名单。
26. **三条出站路径的私网开关是一套，且永不放行云元数据**：`model.allow-private-endpoints`（本地 Ollama）、`webhook.allow-private-targets`（本地接收器）、`mcp.allow-private-servers`（本地自建 MCP server），都走 `SsrfGuard.assertAllowedHttpUrlAllowingPrivate`，dev profile 全开、生产全关。它放行环回与普通私网，但 169.254.0.0/16、100.64.0.0/10、fe80::/10、fd00:ec2::/64 **任何开关都拦**。⚠️ 缺任何一个开关都会让对应场景在本地根本调不通，而这不是「不可验证」，是开关没配齐——MCP 那个就是 2026-09-04 补的。⚠️ 「永不放行云元数据」这半条是**真机冒烟点出来的**：原实现打开开关后只校验 URL 形态，dev 下把模型 endpoint 填成 `http://100.100.100.200/v1`（阿里云元数据）能成功落库，而当时单测是绿的——断言把「只校验形态」写成了预期，测试固化了错误行为。改这几个开关时先问一句：放开的是「本地地址」还是「连元数据一起」。
27. **MCP 登记时不校验 URL、只在同步时校验，这与 Webhook「落库就拦」的差异是有意的**：MCP 有 `lastSyncError` + 界面警示条这条设计好的失败反馈通道，错误立即可见；Webhook 配错地址是在事件推送时静默失败，用户不会主动看投递表，所以必须落库就拦。别为了「一致」把 MCP 也改成落库拦。
28. **租户级存储配额只算对象存储**：`StorageUsageDao` 求 `document.file_size + chat_attachment.file_size`，按套餐配 `billing.quota.<PLAN>.storage-bytes`（FREE 1GB / PRO 20GB / ENTERPRISE 不限，0=不限）。⚠️ 爬取的 URL 类文档 `file_size` 为 null、不占 S3，**刻意不计入**，那条链路由 `max-pages-limit`（500）约束。检查点在知识库上传与附件上传两处、都在传 S3 之前；统计失败 fail-open 放行。⚠️ `KnowledgeServiceImpl` 的 `QuotaService` 是 setter 注入（构造函数被 10 个单测手工调用），没注入会 NPE 而不是静默跳过。
29. **`sa-token.is-log` 保持开启，但日志实现必须是脱敏版**：内置的 `SaLogForConsole` 会把完整会话凭证打进 INFO 且直接 `System.out`（logback 的 pattern 过滤够不到）。`SaTokenConfig.installMaskingLog` 在 `@PostConstruct` 里换成 `TokenMaskingSaLog`——复用 Sa-Token 自己的 `StrFormatter` 渲染后整体正则脱敏，再转交 SLF4J。⚠️ 正则的 `` 词边界不能去掉，否则配置日志里的 `tokenName=satoken` 会被一起脱掉，而那条正是排查「请求头名字配错」时要看的。别把这段当冗余删掉，删了之后 token 会重新进日志且没有任何报错。

30. **应用级配置的写端点只给管理员**：控制器类上标 `@AdminOnlyWrites`，由 `AdminOnlyWritesAspect` 对该类所有 POST/PUT/DELETE/PATCH 强制 `requireTenantAdmin`，读端点不受影响；「用 POST 做查询」的端点（如批量查文档状态）标 `@ReadOnlyEndpoint` 豁免。`WriteEndpointRoleGuardTest` 扫描全部控制器：有写端点的类必须标注解，或登记进白名单并写明理由。⚠️ 2026-09-25 安全扫描前，知识库 / QA / Prompt / 问答策略 / 转人工规则 / A/B / 模型 / 工具 / 技能 / MCP 这 10 个控制器对坐席完全放开。⚠️ 切面**不能**用 `HIGHEST_PRECEDENCE`：会排到 `ExposeInvocationInterceptor` 前面，每次调用直接抛异常，管理员的写操作也全部 500——`AdminOnlyWritesAspectTest` 用真实代理织入，当初正是它抓到的。
31. **凭据字段只写不读**：`AiModelConfig.apiKey`、`AiTool.authHeader`、`McpServer.authHeader` 与 `User.password` 一样标 `@JsonProperty(access = WRITE_ONLY)`——实体直接当响应体，此前明文随列表发给全体登录用户。⚠️ 不能改成 `@JsonIgnore`：create 端点直接用实体收请求体，那样新建时填的密钥会静默丢失。`CredentialNotSerializedTest` 两个方向都钉着。前端编辑弹窗本就不回显凭据，不依赖响应里的值。
32. **登录防爆破两层**：按 IP 限流（登录 20/分、注册 5/分）挡单一来源；按用户名锁定（连续失败 5 次锁 15 分钟）挡「换 IP 猜同一账号」。锁定检查在校验密码**之前**，否则锁定期内猜中照样放行。只有 `BadCredentialsException` 计数——账号停用、租户冻结时密码其实是对的，计进去会把人锁在本就进不去的门外；靠匹配报错文案区分太脆弱，所以单独成类。不存在的用户名同样计数，否则锁不锁本身就能探测用户名。⚠️ 已知代价：知道用户名的人能故意把别人锁 15 分钟，根治要验证码。test profile 关掉 IP 限流（MockMvc 全部来自 127.0.0.1），单测覆盖。
33. **账号 / 租户状态变化即吊销登录态**（`SessionRevocationService`）：改角色、停用、删号、管理员重置他人密码 → 踢掉该用户全部 token；本人改密码 → 只踢其他设备；冻结、改成已过期、删除租户 → 踢掉租户下全部用户。⚠️ 角色存在会话里（`SecurityUtil.getRole` 读 session），不踢的话降级要等对方自己重登才生效。套餐**自然到期**没有操作可以挂钩，由 `TenantExpiryScheduler` 补上：默认每 10 分钟把「ACTIVE 且已过 `expireTime`」的租户置为 EXPIRED 并踢人，互斥靠条件更新 `transitionStatus`（只有改成功的一方踢人）。⚠️ `transitionStatus` 上的 `@Transactional` 是承重的：调度线程没有事务，去掉它条件更新直接抛异常、被逐租户的 catch 吞成一条 WARN，租户永远停不掉——`MemberPrivilegeIT` 那条到期用例钉着。续费时延长到期时间会自动恢复 ACTIVE；到期时间没延长就点「恢复激活」会被拦下。`MemberPrivilegeIT` 的两条用例证明旧 token 真的变 401。
34. **自助注册基线关闭**：平台配置中心的 `platform.registration.enabled` 优先，库里没设时取 `qingyu.care.auth.self-register-enabled`（基线 false，dev/test true）。登录页经免登录的 `GET /v1/auth/config` 决定是否显示注册入口，拿不到结果时按关闭处理。此前库里没设时默认开启，且系统没有任何验证通道。
35. **占位符密钥拒绝启动**：`ProductionSecretsGuard` 在非 dev/test profile 下检查数据库、对象存储、平台管理员口令、Redis 四个密钥，任一仍含 `change-me` 即启动失败并列出变量名。demo profile 同样要拦（对外演示环境）。检查按**实际生效的属性值**进行（`EFFECTIVE_SECRETS`，环境变量最终都落到这些属性上），同时拒绝仓库里写死过的默认口令；新增密钥类配置时同步加进去。生产 compose 要求必须设置 `REDIS_PASSWORD`，Redis 健康检查必须判输出是 `PONG`（`redis-cli` 认证失败时退出码仍是 0）。⚠️ **`RateLimitConfig` 为 Bucket4j 自建 Lettuce 连接，不继承 `spring.data.redis.password`**：曾只拼 host:port，Redis 一加密码就每次 NOAUTH、按设计 fail-open，开放 API 与登录的全部限流静默失效，只留 WARN。自动化测试连的都是无密码 Redis，2026-09-27 真机冒烟连带密码的 Redis 才抓到；`RateLimitRedisPasswordIT` 用带密码容器守着。新增任何自建 Redis 连接都要带上密码。
36. **注册验证码 fail-closed，Turnstile secret 只写不读**：平台配置 `platform.registration.captcha` 选 `NONE`/`IMAGE`/`TURNSTILE`（`CaptchaService`）。与限流相反，Redis 或 Cloudflare 不可达时**拒绝**注册——验证码一放行就等于没开。图形验证码答案存 Redis 并用 GETDEL 取出即删，答错也作废（用 get 则同一 id 可无限重猜）；校验排在「用户名已存在」检查**之前**，否则不过验证码也能逐个探测账号；免登录的出图端点按 IP 限流且仅 IMAGE 模式可用。⚠️ 校验必须在事务**外**：`AuthService.register` 用 `TransactionTemplate` 只包建租户与建用户，Turnstile 同步请求 Cloudflare 最坏 13 秒，包进事务就一直占着数据库连接，Cloudflare 一慢能把连接池占满拖垮全站（代码审查发现）。`GET /v1/platform/config` 对 secret 返回掩码，`PUT` 时空串或原样回传的掩码都视为「不修改」；切到 TURNSTILE 而 site key / secret 没配齐时拒绝保存（放过去注册入口整个不可用、保存时毫无提示）。平台配置页的「测试 Turnstile」用表单**当前值**真实请求一次 siteverify（secret 留空用已保存的），Cloudflare 官方测试密钥 `1x00000000000000000000AA` / `1x0000000000000000000000000000000AA`（必过）、`2x0000000000000000000000000000000AA`（必败）可用于本地冒烟。⚠️ 登录端点仍无验证码，第 32 条「知道用户名能把人锁 15 分钟」的代价仍在。

37. **客户端 IP 由反代保证可信，后端不自己解析转发头**：`forward-headers-strategy: framework` 注册的 `ForwardedHeaderFilter` 会把 `X-Forwarded-For` / `Forwarded` 从请求头里**藏掉**，并用 `Forwarded: for=` 或 XFF 的**第一段**改写 `getRemoteAddr()`。所以：① 后端一律取 `getRemoteAddr()`，自己读 XFF 恒为 null；② nginx 必须用 `$remote_addr` **覆盖**（不是 `$proxy_add_x_forwarded_for` 追加）XFF，并清空客户端自带的 `Forwarded`、`X-Forwarded-Port`，`X-Forwarded-Host` 与 `Host` 由 nginx 覆盖成带端口的 `$http_host`；前面若还有 CDN / 负载均衡，用 realip 模块先还原 `$remote_addr`，别改回追加模式。⚠️ 2026-09-30 安全审查 H2：此前代码「取 XFF 最后一段」、nginx 用追加模式——前者在生产上根本执行不到（头已被藏），实际生效的是客户端自填的第一段，登录 / 注册 / 出图 / 访客的按 IP 限流全部可被伪造 IP 绕过、审计 IP 可伪造。当时的单测直接 mock `getHeader`、没经过过滤器，正常流量下第一段又恰好是真实 IP，所以一直绿、一直看起来正常。`ClientIpResolutionTest`（走真实过滤器）+ `NginxForwardedHeadersTest`（`frontend/nginx.conf` 与部署文档样例两份）守着。 ⚠️ `X-Forwarded-Host` 不能只清空：`ForwardedHeaderFilter` 一看到 `X-Forwarded-Proto` 就把端口重置成协议默认值，前端不在 80/443（compose 的 `FRONTEND_PORT`）时同源请求被判跨域、整个后台登录不了——2026-10-01 用真实 nginx 容器冒烟发现，且修改前的配置（`Host $host` 不带端口）本来就有这个问题。
38. **异步线程里不能现查「靠过滤器隔离」的配置**：`TenantDataAspect` 对「无 TenantContext + 未登录」一律不加过滤（登录与开放 API 鉴权要按全局唯一键跨租户查），而 `@Async` / `@Scheduled` 线程两个条件都满足——在那里调 `ModelRouterService.getModelsForScenario` / `callWithFallback` 拿到的是**全平台所有租户**的模型。2026-09-30 安全审查 H1：QA 生成就这么把 A 租户的文档全文发到了 B 租户配置的 endpoint（B 把 `priority` 填成最小值即可排第一）。做法：在请求线程解析好模型列表，异步方法用 `callWithModels(models, …)`；`QaGenerationService.generateFromDocument` 的签名强制带这个参数。`QaGenerationServiceTest` + `QaPairControllerGenerateTest` 守着。 机制层另有兜底：`ModelRouterService.mergeTenantAndShared` 在「没有租户上下文且不在请求线程」时直接抛异常，新的后台调用方会立刻报错而不是静默拿到全平台模型（`ModelRouterServiceMergeTest` 守着）。新增异步任务要用到任何派生查询时同理——要么请求线程查好传进去，要么像 `SiteCrawlService.runCrawl` 那样设上下文并 `finally` 清理。
39. **出站调用必须有墙钟总时长上限**：`PinnedHttpClientFactory.create` 的连接 / socket / 响应超时都是「两次读之间」的空闲超时，对端先回 200 再每隔几秒滴 1 字节，调用就永远不结束；而 Spring 关闭响应时会把剩余 body 读完（`EntityUtils.consume`），连只取状态码的 Webhook 也躲不掉。三条 Apache 路径都包在 `PinnedHttpClientFactory.callWithDeadline` 里：到点由看门狗 `close(CloseMode.IMMEDIATE)` 掉这次调用专用的客户端，触发过一律按失败算（Spring 会吞掉关闭时的 IOException，调用看似正常返回）。总时长：Webhook = 2×`timeout-ms`、HTTP 工具 = 2×单段超时、网页抓取 30 秒。Webhook 拿到状态码就立即断开、不读 body。⚠️ 2026-09-30 安全审查 H3：8 个慢速回调地址就能占满 Boot 默认异步池（core 8 + 无界队列），全平台审计 / 计量 / Webhook 一起无限排队；「测试 Webhook」同步占 Tomcat 线程。`PinnedHttpClientDeadlineTest`（本地慢速滴灌服务端，真实 socket）守着。MCP 走 Reactor Netty 的 `requestTimeout`，本就是总时长，不在此列。
40. **HTTP 工具的响应边读边计数**：`RestClientHttpToolExecutor` 读到 1MB（`MAX_RESPONSE_BYTES`）即截断并立刻断开连接，单段超时封顶 30 秒（租户能把 `timeoutMs` 配成 `Integer.MAX_VALUE`）。读到的是 HttpClient 自动解压后的字节，所以 gzip 炸弹同样被挡住。⚠️ 2026-09-30 安全审查 H4：此前 `retrieve().body(String.class)` 整个读进内存、截断在读完之后，一次对话就能把 JVM 打 OOM、所有租户一起宕。非 2xx 只把状态码与 500 字正文片段交给模型，**不带 URL**——Spring 默认的错误消息含请求路径，路径里可能有密钥，而这条消息会被访客诱导复述。`RestClientHttpToolExecutorTest` 守着。
41. **模型 endpoint 出站禁重定向、连接期校验 DNS**：模型调用走 Spring AI → openai-java → OkHttp，不经 `PinnedHttpClientFactory`，而 OkHttp 默认跟随重定向（含 https→http）。`ModelEndpointGuardInterceptor` 挂在每个按租户构造的模型客户端上：它**短路**不调 `chain.proceed`，改用自己关了重定向、`Proxy.NO_PROXY`、`Dns` 过 `SsrfGuard` 的 OkHttp 客户端发同一个请求（超时从外层链继承），再用网络拦截器复核实际连上的 IP（IP 字面量不经 Dns）；3xx 直接判失败。⚠️ 为什么是短路：`SpringAiOpenAiHttpClient.Builder` 只暴露 `interceptor()`，挂的是**应用拦截器**，位于重定向循环外层，调 `proceed` 就等于放任它跟随。⚠️ 2026-09-30 安全审查 M1：此前租户把 endpoint 填成自己的公网服务器、回 `307 → http://169.254.169.254/...`，平台就带着请求体打云元数据；「测试连接」还把上游错误原文回显（现在只给分类：守卫拒绝 / 上游 HTTP 状态码 / 无法连接）。`ModelEndpointRedirectGuardTest` 走真实 Spring AI 调用链，断言内网目标零访问。⚠️ 向量模型同样在此列：2026-10-06 起向量模型改由后台配置、租户可自带端点，`EmbeddingModelRegistry` 构建的每个 `OpenAiEmbeddingModel` 都挂同一个拦截器（`ModelRouterService.endpointGuardInterceptor()`），落库前同样过 `requireValidEndpoint`；保存前的维度探测（`EmbeddingModelProbe`）失败原因也只给分类，复用 `ModelUpstreamErrors`。此前「平台默认的 EmbeddingModel 由平台配置、不在此列」的豁免已不成立。⚠️ 2026-10-06 二期起端点与 Key 挂在供应商连接上：`ModelProviderService.create/update` 落库前同样过 `requireValidEndpoint`；拉模型列表（`RemoteModelLister`）也挂这个拦截器，并加 15 秒总时长与 1MB 响应体上限，失败只给分类。
