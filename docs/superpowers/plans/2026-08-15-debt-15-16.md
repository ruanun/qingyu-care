### Task 2: 第 16 项——`*UpdateRequest` 字段覆盖的扫描哨兵

**Files:**
- Create: `backend/src/test/java/com/qingyu/care/dto/UpdateRequestFieldCoverageTest.java`
- Modify: `docs/技术债清单.md`

**Interfaces:**
- Consumes: 无
- Produces: 无（终点）

**背景与一处必须先纠正的认知**：

清单第 16 项写的是「断言 `*UpdateRequest` 的字段名集合 **⊇** 实体的可变字段名集合」。**这条规则照字面实现是错的、而且有害。**

实测比对（协调者已跑）：4 个 DTO 会红，而每一处遗漏都是**有意且正确**的：

| DTO | 实体有而 DTO 没收 | 为什么应该没收 |
|---|---|---|
| `ApplicationUpdateRequest` | `appKey` / `appSecret` / `webhookSecret` | 凭据，有专用 `POST /{id}/regenerate-secret`、`/regenerate-webhook-secret` 端点 |
| `ApplicationUpdateRequest` | `tenant` | 归属关系，客户端可设 = 跨租户写入（正是技术债第 14 项刚堵掉的那类洞） |
| `TenantUpdateRequest` | `code` | 租户身份键，全仓无任何 `setCode` 调用，事实上不可变 |
| `UserUpdateRequest` | `username` / `tenant` / `lastLoginTime` | 身份 / 归属 / 系统维护字段 |
| `AbTestUpdateRequest` | `startedAt` / `endedAt` | 生命周期时间戳，由 `AbTestService` 的 start/stop 写（第 132、144 行），create 时显式清空 |

⇒ 强行要求「收全」等于**把凭据与归属关系变成客户端可设**。

**正确的规则是：每处遗漏必须被显式声明过，并写明理由。** 目标不是「不许漏」，而是把**静默遗漏**变成**刻意排除**——第 12 项的病根正是「静默」（实体加了字段，没人发现 DTO 没跟上）。

- [ ] **Step 1: 写扫描哨兵**

创建 `backend/src/test/java/com/qingyu/care/dto/UpdateRequestFieldCoverageTest.java`。

结构：

1. 一张 `Map<String, Map<String,String>>` 白名单：DTO 简单类名 → （字段名 → **刻意排除的理由**）。理由是给人读的，写清楚「为什么这个字段不该由客户端设」。
2. 一张 DTO 类 → 对应实体类的映射（`AiToolUpdateRequest` → `AiTool`、`AbTestUpdateRequest` → `AbExperiment`，其余同名去掉 `UpdateRequest` 后缀即可，但**别用字符串推断类名**，显式列出更可靠）。
3. 反射扫 `com.qingyu.care.dto` 包下全部 `*UpdateRequest`。
4. 对每个 DTO：取实体的**可变实例字段**（排除 `static`/`final`/合成字段，以及 `id`/`createdAt`/`updatedAt`/`tenantId`/`appId` 这几个全局排除项），减去 DTO 已有的字段名，剩下的**必须全部出现在该 DTO 的白名单里**。
5. 失败信息要点名**具体是哪个 DTO 的哪个字段没被声明**，并提示「要么加进 DTO、要么加进白名单并写明理由」。

⚠️ **必须先断言「扫到的 DTO 类数非空」**。扫描逻辑一旦坏掉（包名改了、类名规则变了），循环直接空转、断言退化成「空==空」永真——本仓库 `UpdateRequestNoInitializerTest` 就是先钉这条的，照它的写法。

⚠️ **反过来也要断言**：白名单里若有某个字段其实已经进了 DTO（或实体上压根没这个字段），说明白名单过时了，同样要红。否则白名单会越积越多、变成一张没人敢删的死名单。

⚠️ `tenantId`/`appId` 定义在 `BaseTenantEntity` 上，取实体字段时**要不要包含父类字段**要想清楚：它们已在全局排除项里，但别的父类字段（如果将来有）不该被静默漏掉。建议扫到 `Object` 为止、逐层取 `getDeclaredFields()`。
