### Task 2: 第 12 项后端——三个混合检索参数可通过 API 修改

**Interfaces:**

**背景**：`ChatStrategy` 实体有这三个字段（`hybridEnabled` 混合检索开关、`keywordTopK` 关键词路取回条数、`rrfK` RRF 融合常数），但 `ChatStrategyController.update` **从未给它们赋值**，DTO 化时新写的 `ChatStrategyUpdateRequest` 也没收它们。后果是这三项只能改库。

- [ ] **Step 1: DTO 加三个字段**

在 `ChatStrategyUpdateRequest` 的字段列表末尾加：

```java
    /** 是否启用混合检索（向量 + 关键词） */
    private Boolean hybridEnabled;

    /** 关键词路取回条数 */
    private Integer keywordTopK;

    /** RRF 融合常数 k */
    private Integer rrfK;
```

⚠️ **一律不写初始化器**（`= true` / `= 10` 之类都不行）。`UpdateRequestNoInitializerTest` 会扫描全部 `*UpdateRequest` 并强制这条，写了初始化器即红。这条铁律的由来：初始化器会被写进无参构造，而 Jackson 反序列化走的正是那个构造，请求体没给的字段就会拿到默认值而非 `null`，判空恒真、把库里的值静默覆盖掉。

- [ ] **Step 2: 控制器加三行赋值**

在 `ChatStrategyController.update` 现有那串 `if (... != null)` 的末尾（`isDefault` 那行之后）加：

```java
        if (strategy.getHybridEnabled() != null) existing.setHybridEnabled(strategy.getHybridEnabled());
        if (strategy.getKeywordTopK() != null) existing.setKeywordTopK(strategy.getKeywordTopK());
        if (strategy.getRrfK() != null) existing.setRrfK(strategy.getRrfK());
```

⚠️ 形状与上面那些逐字一致，别自作主张加校验或改写法。

- [ ] **Step 3: 补一条局部更新回归测试**
