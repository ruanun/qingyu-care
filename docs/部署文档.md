# 轻语（QingYu Care）部署文档

> 适用范围：本文档描述如何从零部署轻语平台（基础设施 + 后端 + 前端 + Widget），以及生产环境的安全与调优要点。
> 本地开发环境搭建请看 [`开发流程文档.md`](./开发流程文档.md)。

## 1. 部署架构总览

```
                       ┌─────────────────────────────┐
  浏览器（管理后台） ──►│  Nginx（静态站 + /api 反代）  │
  客户站点（Widget） ──►│                             │
  第三方服务端 API  ──►└──────────────┬──────────────┘
                                      │ /api
                          ┌───────────▼───────────┐
                          │  后端 Spring Boot     │
                          │  :8080  上下文 /api   │
                          │  （内含 widget.js）    │
                          └───┬───────┬───────┬───┘
                              │       │       │
                    ┌─────────▼─┐ ┌───▼────┐ ┌▼─────────┐
                    │PostgreSQL │ │ RustFS │ │  Redis   │
                    │ pgvector  │ │  (S3)  │ │ 限流/队列 │
                    │ zhparser  │ │ :9000  │ │  :6379   │
                    │  :5432    │ └────────┘ └──────────┘
                    └───────────┘
                              │ OpenAI 兼容协议
                    ┌─────────▼──────────────┐
                    │ 通义千问 DashScope      │
                    │（或任意 OpenAI 兼容端点）│
                    └────────────────────────┘
```

| 组件 | 产物 | 说明 |
|------|------|------|
| 后端 | `backend/target/*.jar` | Spring Boot 可执行 jar，含 Widget 静态资源 `widget.js` |
| 前端管理后台 | `frontend/dist/` | 纯静态文件，由 Nginx（或任意静态服务器）托管 |
| Widget | `backend/.../static/widget.js` | **随后端 jar 发布**，客户站点用 `<script>` 引用，无需单独部署 |
| PostgreSQL 17 | 自定义镜像 `qingyu/pgvector-zhparser:pg17` | 主数据库 + 向量检索（pgvector）+ 中文分词（zhparser） |
| RustFS | 官方镜像 | S3 兼容对象存储，存放知识库原始文档 |
| Redis 7 | 官方镜像 | 限流（Bucket4j）、Webhook 投递队列（Redis Stream）。**可选依赖**：故障时限流 fail-open、队列回退直投，业务不中断 |

## 2. 环境要求

- Docker 与 Docker Compose（基础设施）
- JDK 17+、Maven 3.9+（构建后端）
- Node.js 18+、pnpm（构建前端 / Widget）
- 通义千问 DashScope API Key（或任意 OpenAI 兼容端点的凭据）

## 3. 基础设施部署（Docker Compose）

```bash
cd docker
docker compose up -d
```

`docker/docker-compose.yml` 会启动：

| 服务 | 容器名 | 端口 | 说明 |
|------|--------|------|------|
| postgres | qingyu-postgres | 5432 | 首次 `up` 会**本地构建**自定义镜像（编译 SCWS + zhparser，耗时数分钟；国内网络已内置阿里云 apt 源） |
| rustfs | qingyu-rustfs | 9000（S3）/ 9001（控制台） | S3 兼容存储 |
| redis | qingyu-redis | 6379 | 缓存 / 限流 / Webhook 队列 |
| volume-permission-helper | qingyu-volume-helper | - | 一次性任务：修复 RustFS 卷权限后退出 |
| createbuckets | qingyu-createbuckets | - | 一次性任务：自动创建 `qingyu-care` bucket 并设为公共读 |

首次启动要点：

- `docker/init.sql` 仅在**数据卷首次初始化**时执行：启用 `vector` / `zhparser` 扩展并创建 `chinese_zh` 文本搜索配置。若曾用旧镜像（无 zhparser）初始化过数据卷，需手动进容器执行 `init.sql` 中的扩展语句，或清空 `postgres_data` 卷重建。
- 业务表**不在 init.sql 中**，由后端首次启动时 JPA `ddl-auto: update` 自动创建。
- 数据持久化在命名卷：`postgres_data`、`rustfs_data_0..3`、`redis_data`。

### 默认凭据（⚠️ 生产必须修改）

| 组件 | 账号 / 密码 | 修改位置 |
|------|-------------|----------|
| PostgreSQL | `postgres` / `postgres` | `docker-compose.yml` 环境变量 + 后端 `spring.datasource.*` |
| RustFS | `rustfsadmin` / `rustfsadmin123` | `docker-compose.yml` 环境变量 + 后端环境变量 `STORAGE_ACCESS_KEY` / `STORAGE_SECRET_KEY` |
| Redis | 无密码 | `docker-compose.yml` 加 `--requirepass` + 后端 Redis 配置 |

## 4. 后端部署

### 4.1 构建

```bash
cd backend
mvn clean package            # 含单元测试（纯 Mockito，无需 Docker）
# 或 mvn clean package -DskipTests
```

产物：`backend/target/qingyu-care-*.jar`（Widget 的 `widget.js` 已打包在内）。

### 4.2 环境变量

| 变量 | 默认值 | 必填 | 说明 |
|------|--------|------|------|
| `DASHSCOPE_API_KEY` | - | ✅ | 通义千问 API Key（或兼容端点的 Key） |
| `AI_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode` | | 任意 OpenAI 兼容端点 |
| `AI_CHAT_MODEL` | `qwen-plus` | | 对话模型 |
| `AI_EMBEDDING_MODEL` | `text-embedding-v3` | | 向量模型。**更换后须保证维度与 `spring.ai.vectorstore.pgvector.dimensions`（默认 1024）一致**，否则检索报错；已有向量数据需重新摄取 |
| `REDIS_HOST` / `REDIS_PORT` | `localhost` / `6379` | | Redis 地址 |
| `STORAGE_ENDPOINT` | `http://localhost:9000` | | S3 端点 |
| `STORAGE_ACCESS_KEY` / `STORAGE_SECRET_KEY` | `rustfsadmin` / `rustfsadmin123` | | S3 凭据 |
| `STORAGE_BUCKET` | `qingyu-care` | | S3 bucket |

数据库连接（`spring.datasource.*`）默认指向 `localhost:5432/qingyu_care`，非本机部署时用 Spring 标准方式覆盖（环境变量 `SPRING_DATASOURCE_URL` 等或外置配置文件）。

### 4.3 运行

```bash
export DASHSCOPE_API_KEY=your-key
java -jar qingyu-care-*.jar                                  # 默认配置（生产建议）
java -jar qingyu-care-*.jar --spring.profiles.active=dev     # 开发（SQL 日志更详细）
```

- 服务端口 `8080`，上下文路径 `/api`（所有接口都在 `/api` 前缀下）。
- 健康检查：`GET /api/actuator/health`。Redis 健康检查已刻意关闭（Redis 是可选依赖，不应拖垮整体健康状态）。
- Swagger：`/api/swagger-ui.html`（生产建议在网关层屏蔽）。

### 4.4 数据库表结构管理

- 项目**未接入 Flyway/Liquibase**：表结构由 JPA `ddl-auto: update` 在启动时自动增量创建/更新（`schema.sql` 仅是参考文档，不参与建表）。
- `backend/src/main/resources/migration/` 下是**一次性手工迁移脚本**（脚本头部注释有执行方式与幂等说明）。升级版本时检查该目录是否有新脚本需要执行：

```bash
docker exec -i qingyu-postgres psql -U postgres -d qingyu_care < backend/src/main/resources/migration/xxx.sql
```

## 5. 前端部署

### 5.1 构建

```bash
cd frontend
pnpm install
pnpm build       # 产物在 frontend/dist/
```

### 5.2 Nginx 托管示例

前端是纯静态 SPA，需要把 `/api` 反代到后端，并对 SSE 流式接口关闭缓冲：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 管理后台静态站
    root /var/www/qingyu-care/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退
    }

    # 后端 API（上下文路径就是 /api，直接透传）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式对话（/api/chat/stream、/api/open/v1/chat/stream）必需：
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        chunked_transfer_encoding on;

        # 知识库文档上传（后端限制单文件 100MB / 请求 200MB）
        client_max_body_size 200m;
    }
}
```

## 6. Widget 部署与接入

Widget 不需要单独部署——`widget.js` 是后端 jar 内的静态资源。客户站点接入：

```html
<script src="https://your-domain.com/api/widget.js?appKey=YOUR_APP_KEY" defer></script>
```

- `appKey` 即管理后台「应用管理」中的 App Key。
- 浏览器侧鉴权走 **Origin 白名单**：必须在应用配置的「允许来源（allowedOrigins）」中加入客户站点域名，否则开放 API 返回 403。
- 服务端集成（非浏览器）则使用 `X-App-Id` + `X-Api-Key` 头调用 `/api/open/v1/**`，超限返回 429 + `Retry-After`。

## 7. 生产环境安全与调优清单

部署到生产前逐项过一遍：

- [ ] **修改全部默认凭据**（PostgreSQL / RustFS，见第 3 节），Redis 加密码。
- [ ] **收紧端口暴露**：5432 / 9000 / 9001 / 6379 不对公网开放（compose 里改为仅绑定内网，或删掉 `ports` 走容器网络）。8080 只经 Nginx 反代访问。
- [ ] **启用 HTTPS**：Widget 嵌入第三方站点、开放 API 签名头都应走 TLS。
- [ ] **RustFS bucket 权限**：compose 默认把 `qingyu-care` bucket 设为公共读（`mc anonymous set public`），生产按需收紧为私有 + 预签名 URL。
- [ ] **日志级别**：`application.yml` 默认 `com.qingyu.care: DEBUG`、`org.springframework.ai: DEBUG`，生产覆盖为 `INFO`。
- [ ] **屏蔽 Swagger**（`/api/swagger-ui.html`、`/api/v3/api-docs`）或加访问控制。
- [ ] **限流与额度**：开放 API 默认每应用 60 次/分钟（`qingyu.care.openapi.default-rate-limit-per-minute`，应用级可覆盖）；租户月度额度按套餐（FREE/PRO/ENTERPRISE）生效，超额 403 `QUOTA_EXCEEDED`。
- [ ] **知道 Redis 的降级语义**：Redis 故障时限流放行（fail-open）、Webhook 队列回退 `@Async` 直投、DB 重试扫描兜底——业务不中断，但限流失效期间需关注上游告警。
- [ ] **Webhook 出网**：后端需能访问租户配置的回调地址；投递签名头为 `X-Qingyu-Signature: sha256=...`（HMAC-SHA256），退避重试参数见 `qingyu.care.webhook.*`。
- [ ] **`ddl-auto: update` 的边界**：只增不删（不会删列/删表/收窄类型），大版本升级前仍应先备份再启动新版本。

## 8. 备份与升级

### 备份

```bash
# 数据库逻辑备份（推荐纳入定时任务）
docker exec qingyu-postgres pg_dump -U postgres qingyu_care > backup_$(date +%F).sql

# 对象存储：备份 rustfs_data_* 卷，或用 mc mirror 同步到异地
```

### 升级流程

1. 备份数据库（见上）。
2. 检查 `backend/src/main/resources/migration/` 是否新增了需要手工执行的脚本。
3. 构建新版 jar（Widget 有改动时其产物已包含在 jar 内，客户站点无需变更嵌入代码）。
4. 替换 jar 重启后端（JPA 自动增量更新表结构）；重新发布 `frontend/dist`。
5. 验证：`/api/actuator/health` 为 UP，管理后台可登录，Widget 站点可正常对话。

回滚：换回旧 jar 即可（`ddl-auto: update` 只增不删，旧版本兼容新增列）；数据异常时用备份恢复。

## 9. 常见问题排查

| 现象 | 排查方向 |
|------|----------|
| 启动报 pgvector 相关错误 | 数据卷是否用本项目镜像初始化：`docker exec qingyu-postgres psql -U postgres -d qingyu_care -c "\dx"` 应能看到 `vector` 与 `zhparser` |
| 混合检索/中文关键词检索报错 | 同上确认 `zhparser` 扩展与 `chinese_zh` 配置存在（旧数据卷未执行新版 init.sql 是常见原因） |
| 向量检索报维度不匹配 | 更换了 embedding 模型但未同步 `pgvector.dimensions`，或未重建已有向量数据 |
| 文档上传失败 | RustFS 是否健康（`:9000/health`）、bucket 是否存在、`STORAGE_*` 凭据是否正确 |
| 流式回答卡住不出字 | Nginx 未关闭 `proxy_buffering`（见 5.2） |
| Widget 站点 403 | 应用的 allowedOrigins 未包含该站点 Origin（协议+域名+端口需完全一致） |
| 开放 API 429 | 触发应用级限流，按 `Retry-After` 重试或调高应用限流配置 |
| 开放 API 403 `QUOTA_EXCEEDED` | 租户月度额度用尽，升级套餐或等待月度自然重置 |
